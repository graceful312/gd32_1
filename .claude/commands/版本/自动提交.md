# 版本自动提交

在完成一次较大改动或更新后，自动将变更保存到 Git 并用中文撰写详细的提交说明。

## 执行流程

### 第一步：检查变更

运行以下命令获取当前状态：
- `git status` — 查看有哪些文件被修改、新增、删除
- `git diff` — 查看已跟踪文件的具体改动
- `git diff --cached` — 查看已暂存的改动
- `git log --oneline -5` — 查看最近的提交记录，保持风格一致

### 第二步：判断是否值得提交

如果没有任何变更（`git status` 显示 clean），直接告知用户"没有需要提交的变更"，结束流程。

如果变更量很小（例如只改了一两个注释、拼写修正），询问用户是否要提交，还是等攒更多改动再一起提交。

### 第三步：分析变更内容

逐文件分析改动，理解：
- 改了什么（新增/修改/删除了哪些函数、变量、配置）
- 为什么改（功能新增、Bug修复、重构、配置调整、注释补充）

### 第四步：撰写中文提交说明

提交说明格式：
```
<类型>: <简要描述>

<详细变更列表，每个文件一行>
```

类型前缀：
- `新增` — 新文件、新功能
- `修改` — 功能调整、逻辑变更
- `修复` — Bug修复
- `重构` — 代码结构优化，不改变功能
- `配置` — 引脚、宏定义、工程配置变更
- `注释` — 纯注释/文档变更

详细变更列表示例：
```
新增 RTC 模块（HardWare/RTC.c, RTC.h）
- 实现日历读写、闹钟、唤醒定时器、备份寄存器功能
- 使用 LXTAL 32.768kHz 作为时钟源
- RTC_Init() 已加入 System_Init() 初始化流程
修改 HeaderFiles.h — 添加 RTC.h 包含
修改 Function.c — System_Init() 中调用 RTC_Init()
```

### 第五步：提交

依次执行：
1. `git add <变更文件>` — 只添加本次相关的文件，不要用 `git add .`
2. `git commit -m "$(cat <<'EOF'\n<提交说明>\nEOF\n)"` — 用 HEREDOC 格式提交
3. `git status` — 验证提交成功

### 第六步：告知结果

向用户报告：
- 提交的 commit hash 和简要说明
- 列出本次提交包含的文件清单

## 注意事项

- 不要提交 `.claude/` 目录、编译产物（`project/Objects/`）、`.uvoptx` 等 IDE 临时文件
- 如果用户明确要求提交某些敏感文件（如 .env），提醒用户确认
- 不要自动 push 到远程，只做本地提交
- 如果 `git status` 中有未跟踪的新文件，需要确认是否纳入本次提交
