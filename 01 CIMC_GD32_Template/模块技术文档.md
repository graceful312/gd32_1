# CIMC IHD V0.4 模块技术文档

> 目标芯片：GD32F470VET6（Cortex-M4, 168 MHz）
> 开发板：CIMC IHD V0.4
> 开发环境：Keil uVision MDK-ARM, ARMCC V5.06
> 标准外设库：GD32F4xx SPL V2.6.4

---

## 一、整体架构

### 1.1 分层结构

```
main.c (入口)
  └── Function.c (应用层)
        ├── System_Init() — 依次初始化所有外设
        ├── UsrFunction() — 用户主循环
        └── FatFs — 文件系统（独立于 HeaderFiles.h）
              └── diskio.c — 底层对接 SPI Flash
                    └── SPI_Flash.c — GD25Q40ESIGR NOR Flash 驱动
```

### 1.2 包含关系

所有模块 `.c` 文件只 `#include "HeaderFiles.h"`，由它统一引入全部头文件（中心辐射模式）。

**例外**：FatFs 未纳入 `HeaderFiles.h`，使用 FatFs 的文件需自行 `#include "../FatFs/FatFs.h"`。

### 1.3 程序启动流程

```
main()
  → System_Init()
      1. LP_Init()          — PMU 时钟使能，检测唤醒来源
      2. systick_config()   — 系统时钟 168MHz
      3. Key_Init()         — 按键 GPIO
      4. LED_Init()         — LED GPIO
      5. OLED_Init()        — OLED 显示屏
      6. Serial_Init()      — USART2 串口
      7. 打印唤醒来源
      8. Timer1_Init()      — 1kHz 定时器中断
      9. ADC_port_init()    — 内部 ADC
     10. DAC_Init()         — DAC
     11. GD30AD3344_Init()  — 外部 ADC
     12. RTC_Init()         — 实时时钟
     13. spi_flash_init()   — SPI Flash
     14. FatFs_Init()       — 文件系统
  → UsrFunction()           — 主循环（永不返回）
```

### 1.4 引脚分配总表

| 外设 | 引脚 | 备注 |
|------|------|------|
| LED1 | PA4 | 高电平点亮，与 DAC_OUT0 共用 |
| LED2 | PA5 | 高电平点亮，与 DAC_OUT1 共用 |
| LED3 | PA0 | 高电平点亮，与 WKUP 引脚共用 |
| LED4 | PA1 | 高电平点亮 |
| KEY3 | PA6 | 上拉输入，低电平有效 |
| KEY4 | PA7 | 上拉输入，低电平有效 |
| USART2 TX | PB10 | AF7 |
| USART2 RX | PC5 | AF7 |
| ADC | PC0 | 模拟输入 |
| DAC OUT0 | PA4 | 模拟输出，12 位 |
| DAC OUT1 | PA5 | 模拟输出，12 位 |
| SPI1 SCK | PB13 | AF5，GD30AD3344 与 SPI Flash 共用 |
| SPI1 MISO | PB14 | AF5，GD30AD3344 的 DRDY 也复用此引脚 |
| SPI1 MOSI | PB15 | AF5 |

## 二、各模块详细说明

### 2.1 LED 模块

**文件**：`HardWare/LED.c` / `HardWare/LED.h`

**设计思路**：最简 GPIO 驱动。LED1/LED2 因与 DAC 共用 PA4/PA5，`LED_Init()` 仅初始化 LED3(PA0) 和 LED4(PA1) 为推挽输出。LED1/LED2 的 ON/OFF 宏仍然保留，但实际使用时需注意与 DAC 的冲突。

**引脚**：LED1=PA4, LED2=PA5, LED3=PA0, LED4=PA1，全部高电平点亮。

**接口**：
- `LED_Init()` — GPIO 时钟使能 + 推挽输出配置
- `LEDx_ON()` / `LEDx_OFF()` — 直接操作 GPIO_BOP/BC 寄存器的宏

**注意事项**：PA0 同时是 WKUP 引脚，进入 Standby 模式前必须关闭 LED3 并将 PA0 重新配置为上拉输入，否则会误触发唤醒。

---

### 2.2 按键模块

**文件**：`HardWare/Key.c` / `HardWare/Key.h`

**设计思路**：状态机消抖 + 多事件检测，不是简单的延时消抖。通过 Timer1 的 1kHz 中断每 1ms 调用 `Key_Tick()`，内部用计数器实现 20ms 采样间隔，既保证消抖又不占用 CPU。

**硬件**：KEY3=PA6, KEY4=PA7，内部上拉，按下为低电平。

**状态机**（5 个状态）：
```
状态 0 (空闲) → 检测到按下 → 状态 1
状态 1 (消抖) → 20ms 后确认 → 状态 4 (长按检测)
状态 4 (长按/连发) → 达到 2000ms → 触发长按事件，之后每 100ms 触发连发
                   → 释放 → 状态 0，触发单击/松开事件
```

双击检测：单击后进入状态 2，等待 200ms 窗口内第二次按下。窗口内无第二次按下则确认为单击。

**事件标志**：
| 标志 | 值 | 说明 |
|------|-----|------|
| KEY_HOLD | 0x01 | 持续按住期间一直置位 |
| KEY_DOWN | 0x02 | 按下边沿 |
| KEY_UP | 0x04 | 释放边沿 |
| KEY_SINGLE | 0x08 | 单击 |
| KEY_DOUBLE | 0x10 | 双击 |
| KEY_LONG | 0x20 | 长按（达到 2 秒触发一次） |
| KEY_REPEAT | 0x40 | 连发（长按后每 100ms 触发） |

**接口**：
- `Key_Init()` — PA6/PA7 上拉输入
- `Key_Check(n, Flag)` — 读取并清除指定事件标志（HOLD 除外，它持续反映状态）
- `Key_Tick()` — 由 Timer1 ISR 调用，1ms 周期

---

### 2.3 定时器模块

**文件**：`HardWare/Timer.c` / `HardWare/Timer.h`

**设计思路**：仅配置 Timer1 产生 1kHz 周期中断，作为整个系统的"心跳"。当前唯一的消费者是按键模块的 `Key_Tick()`。

**配置**：
- 时钟源：168MHz（APB1 经过 ×2 分频后 Timer 时钟 = 168MHz）
- 预分频：167 → 168MHz / 168 = 1MHz
- 自动重载：999 → 1MHz / 1000 = 1kHz
- NVIC：2 位抢占 + 2 位子优先级，抢占优先级 2，子优先级 1

**中断处理**：`TIMER1_IRQHandler()` 清除更新标志后调用 `Key_Tick()`。

**注意事项**：NVIC 优先级分组在 `Timer1_Init()` 中设置为 Group2（2 位抢占 + 2 位子），这是整个系统的分组设置，只需调用一次。

---

### 2.4 OLED 显示模块

**文件**：`HardWare/OLED.c` / `HardWare/OLED.h` / `HardWare/OLEDfont.h`

**设计思路**：软件模拟 I2C（位操作）驱动 SSD1306 控制器，采用显存（GRAM）机制——所有绘图操作先写入 RAM 缓冲区，最后通过 `OLED_Refresh()` 一次性刷新到屏幕。这样避免了频繁的 I2C 通信，也方便实现复杂图形。

**硬件**：PB8(SCL) / PB9(SDA)，开漏输出，I2C 地址 0x78。分辨率 128×32（4 页 × 8 像素/页）。

**显存**：`volatile u8 OLED_GRAM[144][4]`，128 列 × 4 页。多出的 16 列（144-128）可能是为了边界处理。

**I2C 时序**：
- 控制字节 0x00 = 命令，0x40 = 数据
- `I2C_Start()` 拉高 SDA 后拉低 SCL
- `Send_Byte()` MSB 先发，每个 bit 期间 SCL 先低后高
- `I2C_WaitAck()` 切换 SDA 为输入模式，读取 ACK

**初始化序列**：先 500ms 延时等待上电稳定，然后依次发送：关闭显示 → 设置时钟分频 → 设置多路复用率 → 设置显示偏移 → 设置起始行 → 设置充电泵（使能）→ 设置内存寻址模式（页模式）→ 设置段重映射 → 设置 COM 输出扫描方向 → 设置对比度 → 设置预充电周期 → 设置 VCOMH → 正常显示 → 开启显示。

**绘图功能**：
- 基础：`OLED_DrawPoint()`, `OLED_ClearPoint()`, `OLED_Clear()`
- 几何：`OLED_DrawLine()`（Bresenham 算法）, `OLED_DrawCircle()`（中点画圆）
- 文字：`OLED_ShowChar()`（6×8 / 8×16 字体）, `OLED_ShowString()`, `OLED_ShowNum()`, `OLED_ShowChinese()`
- 图片：`OLED_ShowPicture()`
- 特效：`OLED_ColorTurn()`（反色）, `OLED_DisplayTurn()`（翻转）, `OLED_ScrollDisplay()`（水平滚动中文）

**使用方式**：主循环中先调用各种绘图函数更新显存，最后调用 `OLED_Refresh()` 刷新。

---

### 2.5 串口模块

**文件**：`HardWare/Serial.c` / `HardWare/Serial.h`

**设计思路**：USART2 用于与外部传感器/上位机通信，采用数据包协议收发。接收使用中断方式，通过状态机解析定界符（`$` 开头，`#` 结尾）提取完整数据包。

**硬件**：USART2，PB10(TX)/PC5(RX)，AF7，115200 波特率，8N1。

**数据包协议**：
- 数字传感器：`$Dxxxxxxxx...#`，8 路数字量，每个值占 5 字节
- 模拟传感器：`$A:val1,val2,...,val8#`，8 路模拟量，逗号分隔

**全局状态**：
- `rx_buffer[100]` — 接收缓冲区
- `complete_packet[100]` — 完整数据包
- `digital_values[8]` — 8 路数字传感器值（uint8）
- `analog_values[8]` — 8 路模拟传感器值（uint16）
- `new_packet_flag` — 新数据包标志

**接收流程**：
1. USART2 RXNE 中断触发
2. `USART2_IRQHandler()` 读取数据，调用 `Serial_Receive_Byte()`
3. 状态机：等待 `$` → 累积字符直到 `#` → 拷贝到 `complete_packet` → 置位 `new_packet_flag`
4. 主循环检测标志后调用 `Deal_Digital_Data()` 或 `Deal_Analog_Data()` 解析

**发送接口**：`Serial_SendByte()`, `Serial_SendArray()`, `Serial_SendString()`, `Serial_SendNumber()`

**重定向 printf**：项目通过 `fputc()` 重定向到 USART2，支持 `printf()` 直接输出。

**注意事项**：ARMCC 编译器不支持 UTF-8 中文字符串在 `printf` 中使用（会产生 `#870-D` 警告），串口输出一律使用英文。

### 2.6 ADC 模块（内部）

**文件**：`HardWare/ADC.c` / `HardWare/ADC.h`

**设计思路**：最简配置，使用 GD32F470 内置 ADC0 的单通道连续转换模式。适合读取电位器或简单模拟信号。

**硬件**：PC0 → ADC0 通道 10。

**配置**：
- ADC 时钟：PCLK2 / 8
- 转换模式：连续转换，右对齐
- 采样时间：56 个 ADC 时钟周期
- 触发方式：软件触发

**接口**：
- `ADC_port_init()` — GPIO + 时钟 + ADC 配置 + 启动转换
- `ADC_Init()` — ADC 重配置 + 校准
- `ADC_Read()` — 等待 EOC 标志，返回 12 位结果（0~4095）

---

### 2.7 DAC 模块

**文件**：`HardWare/DAC.c` / `HardWare/DAC.h`

**设计思路**：双通道 DAC 输出，12 位精度。初始化后设置输出值即可，无需额外管理。

**硬件**：PA4=DAC_OUT0 (通道 0)，PA5=DAC_OUT1 (通道 1)。

**引脚冲突**：PA4/PA5 同时是 LED1/LED2 的引脚。DAC 初始化时将引脚设为模拟模式（断开数字通路），此时 LED 宏操作无效。

**接口**：
- `DAC_Init()` — DAC 时钟使能，PA4/PA5 设为模拟模式，使能输出缓冲，初始值 0
- `DAC_SetValue(channel, value)` — channel 为 `DAC_CH0`(0) 或 `DAC_CH1`(1)，value 为 0~4095

---

### 2.8 GD30AD3344 外部 ADC 模块

**文件**：`HardWare/GD30AD3344.c` / `HardWare/GD30AD3344.h` / `HardWare/GD30AD3344_spi.h`

**设计思路**：GD30AD3344 是 16 位 Σ-Δ ADC 芯片，精度远高于 MCU 内部 12 位 ADC。通过 SPI1 通信，MISO 引脚兼做 DRDY（数据就绪）信号，通过 EXTI 中断检测。硬件抽象层（`GD30AD3344_spi.h`）用宏封装了引脚定义和 CS 控制，修改宏即可切换 SPI 端口。

**硬件**：SPI1，PB13(SCK), PB14(MISO/DRDY), PB15(MOSI), PB12(CS)。SPI 模式 CPOL=0/CPHA=1，16 位帧，预分频 32（5.25MHz）。

**寄存器**：
- CONVERSION (0x00) — 16 位转换结果（只读）
- CONFIG (0x01) — 配置寄存器：
  - OS：启动单次转换
  - MUX：通道选择（4 差分 + 4 单端）
  - PGA：增益（±6.144V ~ ±0.064V，6 档）
  - MODE：连续/单次模式
  - DR：数据速率（6.25 ~ 1000 SPS）
  - PULL_UP_EN：内部上拉使能

**当前配置**：单端 AIN0，1000SPS，±4.096V 量程，连续模式。

**关键实现细节**：
- `ad3344_spi_txrx16bit()` — 全双工 16 位 SPI 传输，轮询 TBE/RBNE 标志
- `ad3344_exit_enable()` / `ad3344_exit_disable()` — MISO 引脚在 SPI AF 和 EXTI 输入之间切换，用于 DRDY 中断检测
- `delay_us()` — 软件延时，精度不高但足够 SPI 时序要求

**DRDY 中断**：`EXTI10_15_IRQHandler()` 目前是空桩（TODO），尚未实现中断驱动的转换读取。

### 2.9 RTC 实时时钟模块

**文件**：`HardWare/RTC.c` / `HardWare/RTC.h`

**设计思路**：使用 GD32F470 内置 RTC 外设，外部 32.768kHz LXTAL 晶振提供时基。支持日历读写、闹钟、唤醒定时器和备份寄存器。时间采用 BCD 编码（便于显示），对外接口接受十进制参数，内部自动转换。

**时钟配置**：
- 时钟源：LXTAL 32.768kHz
- 预分频：同步 0xFF (255)，异步 0x7F (127)
- 32768 / (255+1) / (127+1) = 1Hz

**首次初始化检测**：备份寄存器 0（RTC_BKP0）存储标志值 0x32F0。上电后检查此值：
- 不等于 0x32F0 → 首次使用，调用 `rtc_first_setup()` 设置默认时间 2025-01-01 00:00:00
- 等于 0x32F0 → 已有有效时间，直接读取

**备份域保护**：RTC 和备份寄存器属于备份域，修改前需调用 `pmu_backup_write_enable()` 解锁。

**闹钟**：
- 闹钟 0 / 闹钟 1 — 支持按日期、小时、分钟、秒匹配
- 使用 `RTC_ALARM_NONE_MASK` 屏蔽不需要的匹配字段
- 闹钟触发时进入 `RTC_Alarm_IRQHandler()`（目前是 TODO 桩）

**唤醒定时器**：
- 使用 ck_spre（1Hz）时钟
- `RTC_SetWakeup(count)` — count 为 1~65535 秒的唤醒间隔
- 低功耗模块通过此接口配置 Deep-sleep / Standby 的定时唤醒

**备份寄存器**：20 个 32 位寄存器（BKP0~BKP19），VBAT 供电，可用于存储掉电保持数据。

**中断处理**：
- `RTC_Alarm_IRQHandler()` — 清除闹钟标志（TODO：用户回调）
- `RTC_WKUP_IRQHandler()` — 清除唤醒标志（TODO：用户回调）

### 2.10 SPI Flash 模块

**文件**：`HardWare/SPI_Flash.c` / `HardWare/SPI_Flash.h`

**设计思路**：GD25Q40ESIGR 是 4Mbit (512KB) NOR Flash，用于存储文件系统数据。通过 SPI1 通信，与 GD30AD3344 共用总线（同一组 SCK/MISO/MOSI），通过 CS 引脚区分。但两者共享 CS=PB12，因此**不能同时使用**——调用前需确保另一方不在通信中。

**硬件**：SPI1，PB13(SCK), PB14(MISO), PB15(MOSI), PB12(CS)。SPI 模式 0（CPOL=0/CPHA=0），8 位帧，预分频 8（21MHz）。

**注意**：与 GD30AD3344 的 SPI 配置不同（模式 0 vs 模式 1，8 位 vs 16 位，预分频 8 vs 32）。`spi_flash_init()` 会重新配置 SPI1 参数，调用后 GD30AD3344 的配置会被覆盖。

**存储规格**：
- 总容量：512KB
- 页大小：256 字节
- 扇区大小：4KB (4096 字节)
- 写入前必须擦除（NOR Flash 特性：只能将 1 写为 0，擦除将整扇区恢复为 0xFF）

**关键函数**：
- `spi_flash_sector_erase(addr)` — 擦除指定地址所在的 4KB 扇区
- `spi_flash_buffer_erase(addr, len)` — 智能部分擦除：读取扇区到缓冲区，将目标区域填 0xFF，擦除扇区，写回。避免擦除扇区内其他有效数据
- `spi_flash_page_write(buf, addr, len)` — 单页写入（最大 256B），自动处理页边界
- `spi_flash_buffer_write(buf, addr, len)` — 任意长度写入，自动分页
- `spi_flash_buffer_read(buf, addr, len)` — 连续读取，无页边界限制
- `spi_flash_read_id()` — 读取 JEDEC ID（应返回 0xC84013）
- `spi_flash_write_enable()` — 发送 WREN 命令
- `spi_flash_wait_for_write_end()` — 轮询 SR 的 WIP 位等待写入完成

**写入流程**：每次写入/擦除操作遵循：WREN → 命令 + 地址 → 轮询等待完成。

### 2.11 低功耗模块

**文件**：`HardWare/LowPower.c` / `HardWare/LowPower.h`

**设计思路**：封装 GD32F470 的 Deep-sleep 和 Standby 两种低功耗模式，对外提供简洁的 API。核心挑战是休眠前后的外设状态管理——需要正确关闭所有可能阻止休眠或导致误唤醒的外设，并在唤醒后恢复。

**支持的模式**：

| 模式 | 功耗 | SRAM 保持 | 唤醒行为 |
|------|------|-----------|----------|
| Deep-sleep | ~mA 级 | 是 | 从下一条指令继续 |
| Standby | ~μA 级 | 否 | 系统复位，从 main() 重新执行 |

**唤醒源**（可组合）：
| 标志 | 值 | 引脚 | 说明 |
|------|-----|------|------|
| LP_WAKEUP_KEY | 0x01 | PA6 (KEY3) | EXTI 下降沿，仅 Deep-sleep 可用 |
| LP_WAKEUP_RTC | 0x02 | 内部 | RTC 唤醒定时器，1~65535 秒 |
| LP_WAKEUP_PIN | 0x04 | PA0 (WKUP) | WKUP 引脚上升沿 |

**休眠前准备**（`lp_prepare_sleep()`）：
1. `timer_disable(TIMER1)` — **必须**，否则 1kHz 中断会立即唤醒
2. `OLED_DisPlay_Off()` — 关闭 OLED 充电泵（节省约 10mA）
3. `dac_disable()` — 关闭 DAC 两个通道
4. `adc_disable()` — 关闭 ADC
5. 关闭全部 4 个 LED

**唤醒后恢复**（`lp_resume_sleep()`）：
1. `timer_enable(TIMER1)` — 恢复按键扫描
2. `OLED_Init()` — 重新初始化 OLED（充电泵和显示配置需要重新设置）
3. `dac_enable()` / `adc_enable()` — 重新使能

**Deep-sleep 核心调用**：
```c
pmu_to_deepsleepmode(PMU_LDO_LOWPOWER, PMU_LOWDRIVER_DISABLE, WFI_CMD);
```
此函数内部自动保存/恢复 SysTick 和 NVIC ISER 寄存器，唤醒后从该函数的下一条指令继续执行。

**Standby 特殊处理**：
- PA0 冲突：WKUP 引脚 = LED3。进入 Standby 前必须关闭 LED3 并将 PA0 重配置为上拉输入
- `pmu_to_standbymode()` 不返回，唤醒后系统复位
- 通过 `pmu_flag_get(PMU_FLAG_STANDBY)` 在下次启动时判断是否从 Standby 唤醒

**唤醒原因检测**（`LP_GetWakeupReason()`）：
- 检查 PMU_FLAG_STANDBY → 返回 `LP_REASON_STANDBY`
- 检查 PMU_FLAG_WAKEUP → 返回 `LP_REASON_DEEPSLEEP`
- 都没有 → 返回 `LP_REASON_POWERON`

**中断处理**：`EXTI5_9_IRQHandler()` 在 LowPower.c 中实现，清除 EXTI_6 标志后退出，`pmu_to_deepsleepmode` 接管恢复流程。

**使用示例**：
```c
// 按键唤醒深度睡眠
LP_EnterDeepSleep(LP_WAKEUP_KEY, 0);

// RTC 10秒定时唤醒
LP_EnterDeepSleep(LP_WAKEUP_RTC, 10);

// 组合唤醒源
LP_EnterDeepSleep(LP_WAKEUP_KEY | LP_WAKEUP_RTC, 10);

// Standby 最低功耗，RTC 30秒唤醒（唤醒=复位）
LP_EnterStandby(LP_WAKEUP_RTC, 30);
```

### 2.12 FatFs 文件系统模块

**文件**：`FatFs/FatFs.c` / `FatFs/FatFs.h` / `FatFs/ff.c` / `FatFs/ff.h` / `FatFs/ffconf.h` / `FatFs/diskio.c`

**设计思路**：在 512KB SPI Flash 上运行 FatFs R0.09 文件系统，实现标准的 FAT 文件读写。FatFs 未纳入 `HeaderFiles.h`，作为独立模块通过 `#include "../FatFs/FatFs.h"` 引用。

**存储映射**：
- Flash 物理：512KB，4KB 扇区，256B 页
- FatFs 逻辑：1024 个 512B 扇区
- 1 个 Flash 扇区 = 8 个 FatFs 逻辑扇区

**配置**（`ffconf.h`）：
- 代码页 936（GBK 中文文件名）
- 启用 `_USE_MKFS`（支持格式化）
- 单卷，512B 扇区
- 禁用长文件名（8.3 格式）
- 非线程安全（裸机环境）

**初始化**（`FatFs_Init()`）：
1. `disk_initialize(0)` — 初始化底层 SPI Flash，最多重试 3 次
2. `f_mount(0, &fatfs)` — 挂载文件系统
3. 如果返回 `FR_NO_FILESYSTEM`，自动调用 `f_mkfs()` 格式化后重新挂载

**底层 I/O**（`diskio.c`）：
- `disk_initialize()` — 初始化 SPI1，读取 JEDEC ID 验证 0xC84013
- `disk_read()` — 逻辑扇区号 → 字节地址，调用 `spi_flash_buffer_read()`
- `disk_write()` — 读-改-写策略：使用静态 4KB 缓冲区，读出整个 Flash 扇区，修改目标区域，擦除扇区，写回。处理跨扇区写入
- `disk_ioctl()` — 返回扇区数 1024、扇区大小 512、块大小 8
- `get_fattime()` — 当前返回 0（TODO：可对接 RTC 获取真实时间戳）

## 三、设计模式与约定

### 3.1 模块自包含原则

每个模块的初始化代码封装在该模块中：
- 模块 `.c` 文件中实现 `XXX_Init()` 函数，包含时钟使能、GPIO 配置、外设配置等全部初始化步骤
- `System_Init()` 仅负责按顺序调用各模块的 `XXX_Init()`
- 低功耗模块额外封装了 `LP_Init()`，内部完成 PMU 时钟使能和唤醒原因检测

### 3.2 中断处理函数归属

项目约定**不修改** `User/gd32f4xx_it.c`。中断处理函数写在对应驱动模块的 `.c` 文件中：
- `TIMER1_IRQHandler()` → `Timer.c`
- `USART2_IRQHandler()` → `Serial.c`
- `RTC_Alarm_IRQHandler()` / `RTC_WKUP_IRQHandler()` → `RTC.c`
- `EXTI5_9_IRQHandler()` → `LowPower.c`
- `EXTI10_15_IRQHandler()` → `GD30AD3344.c`

### 3.3 SPI1 总线共享

GD30AD3344 和 SPI Flash 共用 SPI1 总线和 CS 引脚（PB12），SPI 配置参数不同。使用时的约束：
- 不能同时访问两个设备
- 切换设备前需要重新初始化 SPI1（各自的 `xxx_init()` 会覆盖配置）
- 未来如需交替使用，应增加互斥保护机制

### 3.4 引脚复用冲突

| 引脚 | 功能 1 | 功能 2 | 解决方案 |
|------|--------|--------|----------|
| PA0 | LED3 (高电平) | WKUP 引脚 | Standby 前关闭 LED3，重配置为上拉输入 |
| PA4 | LED1 (高电平) | DAC_OUT0 | DAC 初始化后 LED1 宏无效（模拟模式断开数字通路） |
| PA5 | LED2 (高电平) | DAC_OUT1 | 同上 |
| PB14 | SPI1 MISO | GD30AD3344 DRDY | 在 SPI AF 和 EXTI 输入间动态切换 |

### 3.5 编译器约束

ARMCC V5.06 不支持 `printf` 中使用 UTF-8 中文字符串（产生 `#870-D` 警告）。所有串口输出使用英文。

### 3.6 GD32 SPL 特殊命名

`RTC_WEDSDAY`（少了一个 E）是库中星期三的宏名，不是 `RTC_WEDNESDAY`。
